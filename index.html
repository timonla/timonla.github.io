{% include tech-stack.html stack="kudoro" %}

Kudoro is a mobile app for overlaying Strava data on photos and videos, with more than 1,500 users. The project started as a simple live data overlay tool for cyclists because the existing solutions were overcomplicated and expensive. Since then, it has pivoted into an all-in-one visual editor for all sports, focusing on summary overlays for activities, segments and training.

For this project I wear all the hats. I make the product and technology decisions, design the UI, build and ship the app, handle customer support, and do the marketing. One of the biggest things I've learned is how important it is to balance technical exploration and building features with actually shipping, talking to users and getting the product in front of people.

My Van

I built my home on wheels over 18 months, from the ground up, turning dreams into SketchUp models, into reality. The process had plenty of ups and downs, and I learned a lot of new skills while overcoming unforeseen challenges along the way.

The van has been my full-time home for more than three years now, and has enabled me to ride my bikes in some of the most beautiful places in Europe.

Building a van with as many requirements as I had, meant an endless stream of compromises. Today I have a compact, fully autonomous, stealth home on wheels, with a proper kitchen, bathroom, and storage for two bikes, that serves as a rolling music studio, office, and workshop.

It is pretty satisfying that all the planning paid off. Even after living in it for more than three years, there are very few decisions I would have made differently, knowing what I know today.

Homepage
{% include tech-stack.html stack="komate" %}

The second React Native app I built, based on the Strava API, was born out of my excitement for cycling fast up mountains. My friends and I wanted to know how to pace our efforts up a climb on a given day, and we wanted to do it with a simple UI using the only true metric of greatness: Strava segments.

I built this project together with a non-technical co-founder and was able to reuse a lot of knowledge from Kudoro. The big challenge was designing a UI that stays simple to use while still allowing the full complexity of our calculations, which combine user data, physics and weather data.

The app is currently still in alpha testing within our friend groups, but it has already helped us take a KOM or two.

GitHub
{% include tech-stack.html stack="flashkill" %}

Flashkill was a browser extension that enhanced the browsing experience on a Counter-Strike league platform for more than 3,000 users.

I built this solution together with my brother. As a user I was frustrated with the experience and felt that something had to be done about it.

We had to make lots of interesting technical decisions, learn about the advantages and limitations of browser extensions, and figure out how to work with a third-party platform. Fetching and caching data while dealing with rate limits were some of the challenges we had to overcome.

Building the project open source also gave me the opportunity to think about development guidelines, project structure and how to use TypeScript effectively in browser extensions. One of the more interesting things I explored was typing background script message protocols.
